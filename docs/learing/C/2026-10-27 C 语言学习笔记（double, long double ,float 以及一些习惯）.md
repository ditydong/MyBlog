> 并不是说精度低的话就用 float，一些科学研究精度高用 double，更高的一些仪器用 long double。首先因为机械语言的特性，计算机储存浮点数是一定会出现精度丢失问题的，比如 overflow 或者其他，不会像 int 类型那样 overflow 之后就占用了存储符号的部分而变成负数，深入的讲解等计算机组成原理理解后再来看。简单来说对于计算机存储信息都是二进制，而浮点数的小数部分一般情况下都是无限循环了，（如果要计算，就是小数部分乘以二，取个位，从做往右放，但是但要输出为十进制是，存储的二进制转换就会发生问题，最后导致的结果就是后面的数字都是有问题的，所以有些需要高精度的领域反而用十进制来表示小数。理解这一点就行了。

#### 处理报错问题

思路很简单，由于电脑编译运行是从上往下的，以及报的错不可能全是独立的，所以需要从上往下该，处理报错问题应该满足：

1.先找输出报错里面行号中的**第一条** error：
- 文件名
- 行号位置
- 严重程度
- 消息正文
具体就是需要工程化的分析：需要什么？找不到什么？那两个类型需要匹配？（比如括号，引号这些基础的）

2.没有报错但是结果是错的

> 这是最麻烦的情况，因为编译器没有报错，不知道哪里出问题了，但是有科学的方法也是能快速排错的（正常很难出现，这种主要来自于写结构体时的事情）

- 输入
    - 讲输入的数据在被处理之前打印出来或者什么能验证其内容的操作（**优先**）
- 处理过程
	- 是否是调用了错误的变量/函数  
- 输出

3.最小实验法

> 依旧是没有报错但是结果错了，就是将有问题的输入和数据处理这两部分进行一个简单的测试
> 核心思路就是排除一切与项目无关的内容，只找那个与结果有关的，最小的那个部分

这是一种思考问题的方向，就是要思考范围缩小，而不是扩大

这里使用的是一个很常见的问题：

> 两个 int 类型的变量转换为 double 会导致丢失小数，这是 C 语言结构导致的问题。
> 
> 但是如果直接将两个 int 类型输出为 %.f 则会乱码或者 0.0，因为这取决于 printf 的输出模式，如果用 %.f 来表示输出，电脑会用 double 识别你的变量（8个字节），但是你的 int 是 4 个字节，就会乱码或者输出为 0；

触类旁通，这只是很简单的例子，在结果出现错误的时候有这种最小实验的思路就可以了

4.预期

> 如果程序能够正常运行，并不是说明这程序是对的，要证明就得有预期，并且和预期相互对比

- 固定输入 ==一定要把具体的值写清楚== 
- 独立计算 ==工程的问题==
- 设立预期 ==尽量明确==
- 一一对照
