> 基于 mkdocs，本来基于官方文档花了几小时在本地搭建了一个的，但是一直拖延就没有上传，这个仓库还是使用 DSH 自动搭建的

## 基本内容

- 学习笔记
- 一些想法
- 一些记录

> 没做什么项目，会努力的

**怎么去学习**：
- 听到一个方法
- 用自己的话说清楚
- 放到自己的事情里面试一下
- 根据反馈修改

## 关于博客维护

### 方向

> 如 README 所言，是一个记录学习成长和项目的地方，但是如果仅仅作为这个是作用不大的，所以方向是做成类似 coursebook 的模式，相当于做成一个教程，这就意味着需要增加全面性和持续更新性，还有就是有结构化

在 obsidian 里面更新后不要立即提交，就 commit 到 main 的一个分支里面，等到维护的时间合并
### 规范

- 两位数加下划线加单词
- 图片塞到相对目录，命令以模块代号加序号
- 少用 4级 及以下标题（mkdocs #### 和加粗的大小差不多）
- 空格
	- 汉字与英文字母
	- 数字与英文字母
- 换行
	- 只要是不同类型都换一行
- 代码块 20 左右换行

### 维护

**学习 python**写一些能够高效维护的脚本

- 每周维护一次
	- 30 分钟以内
	- 更新本周知识点
	- 调整状态标记
	- 更新失效链接
